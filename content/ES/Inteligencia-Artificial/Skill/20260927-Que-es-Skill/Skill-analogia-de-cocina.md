
# Qué es un Skill, explicación con analogía de cocina

## Imagina que soy un robot en una cocina

Yo ya sé cocinar "básico" (pensar, hablar, razonar). Pero si me piden hacer **sushi**, igual no sé exactamente cómo.

Ahí entran los **skills** (habilidades): son como **fichas de instrucciones** que guardo en mi mochila.

## ¿Qué es un skill técnicamente?

Un skill es básicamente **una carpeta con un archivo de instrucciones** (llamado `SKILL.md`) que me explica:

1. **Cuándo usarlo** — "cuando el usuario pida hacer una presentación"
2. **Cómo hacerlo** — los pasos, comandos, trucos
3. **Qué herramientas usar** — por ejemplo, un programa para generar archivos PowerPoint

Ejemplo real de los que tengo instalados:

| Skill | Para qué sirve |
|-------|----------------|
| `excel-xlsx` | Crear y leer hojas de cálculo Excel |
| `weather` | Consultar el tiempo |
| `meme-maker` | Crear memes |
| `pdf-generator` | Generar archivos PDF |

## ¿Por qué existe esto?

Piénsalo como un programador:

- **Sin skills**: tendría TODO el conocimiento dentro de mi "cerebro" (el modelo). Sería gigantesco, caro y difícil de actualizar.
- **Con skills**: mi cerebro se mantiene ligero. Cuando necesito algo especial, **leo la ficha de instrucciones justo en ese momento**, la sigo, y listo.

Es parecido a cómo tú no memorizas toda la sintaxis de Python: la buscas en la documentación cuando la necesitas.

## El truco clave 💡

Los skills son **archivos de texto normales**. Cualquiera puede crear uno: escribes un `SKILL.md` explicando qué hacer, y ya tienes una nueva habilidad. Es como instalar un "mod" a un videojuego: el juego base sigue igual, pero ahora sabe hacer algo nuevo.

**Resumen en una frase:** un skill es un manual de instrucciones que cargo bajo demanda para saber hacer tareas específicas sin tenerlo todo memorizado. 📦


# ¿Es mejor usar un Skill para programar, para no usar tanta capacidad de un modelo y así gastar menos dinero y ser más eficiente?

Casi... pero ahí hay un matiz importante que conviene corregir. 🤓

## La verdad: los skills **no ahorran dinero** (al revés)

Cuando cargo un skill, esas instrucciones **entran en mi contexto** — o sea, las leo y eso **consume tokens** (y tokens = dinero). Usar un skill de programar hace la conversación un poco *más* larga, no más corta.

Entonces, ¿para qué sirven realmente?

## El beneficio real: **calidad, no ahorro**

Piénsalo como un estudiante en un examen:

- **Sin skill**: intento programar de memoria. A veces acierto, a veces invento funciones que no existen (eso se llama "alucinar").
- **Con skill**: abro el manual justo antes de empezar. Sigo una guía probada, uso los comandos correctos, evito errores típicos.

Es como un examen de **libro abierto** vs **de memoria**: el libro abierto no hace que pienses menos, hace que **aciertes más**.

## ¿Dónde SÍ hay ahorro real?

El ahorro no está en el skill en sí, sino en **no necesitar un modelo gigante para todo**:

- Tareas tontas (resumir un texto) → modelo pequeño y barato
- Tareas complejas (programar un sistema) → modelo grande
- El skill asegura que la tarea se haga **bien a la primera**, y eso sí ahorra dinero: menos intentos fallidos, menos correcciones, menos tiempo.

## Resumen honesto

| Creencia | Realidad |
|----------|----------|
| "El skill ahorra tokens" | ❌ Al revés, los gasta (lee instrucciones) |
| "El skill hace todo más barato" | ❌ No directamente |
| "El skill hace el trabajo **mejor y más consistente**" | ✅ Ese es el punto |
| "Menos errores = menos correcciones = más eficiente" | ✅ Aquí está el ahorro |

Así que tu intuición tenía algo de cierto (más eficiencia), pero el mecanismo no es "gastar menos capacidad del modelo" — es **invertir unos tokens extra en instrucciones buenas para no cagarla después**. 🎯
